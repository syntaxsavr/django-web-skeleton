How this skeleton works

Each block below demonstrates one mechanism. Open the page source: the markup is the documentation.

1 · Scroll reveal

Elements below the fold fade and rise in as they enter the viewport, staggered by 45ms. Any element with data-reveal joins the system. It turns itself off for reduced motion and print.

2 · Hero entrance

A section marked data-hero-entrance sequences its data-hero-item children on load. The home page hero uses it with a Lottie stage.

First: the kicker line.

Second: the supporting copy.

Third: the actions arrive.

3 · Lottie mounts

One declarative attribute per animation. The ratio box reserves space before the JSON loads, offscreen animations pause, and reduced motion parks on a static frame.

This animation is generated by tools/lottie/build_demo.py: shape layers only, no external assets.

4 · Network-lazy section

Everything under this heading was fetched when you approached it. View source now and it is already swapped in; reload with the network tab open to watch it happen.

5 · Tracking hooks

Every interactive element can carry data-track. Events only push to the dataLayer when analytics consent exists. Watch window.dataLayer in the console.

Outbound link (snatched by middleware)

6 · Consent manager

Klaro! renders the banner only when the master switch is on. The footer holds a Cookie settings button, and legal pages never auto-open it.

7 · The contact form

Honeypot, signed time-trap, Turnstile (when keys are configured) and rate limiting. Submit once and try again immediately to see the cooldown.
